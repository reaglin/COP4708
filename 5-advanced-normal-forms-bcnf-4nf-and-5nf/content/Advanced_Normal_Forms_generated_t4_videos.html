Introduction

Functional dependencies drive normalization up through Boyce-Codd Normal Form, but they do not capture every kind of redundancy. A multivalued dependency (MVD) arises when one attribute determines a set of values for another attribute independently of the rest of the relation. The classic symptom is a table that stores two unrelated repeating facts about the same key — for example, an instructor's courses and the instructor's assigned textbooks or hobbies — forcing you to store every combination of the two sets. The table can be in BCNF (its only functional dependency may be the trivial one on the full key) and still be full of repeated rows that cause update anomalies.

Fourth Normal Form addresses exactly this situation. A relation is in 4NF if it is in BCNF and, for every nontrivial multivalued dependency X ->> Y, X is a superkey. The repair is decomposition: split the relation so each independent multivalued fact lives in its own table, which by Fagin's theorem produces a lossless join. In this course, 4NF sits between BCNF and 5NF in the sequence you will apply to a complete schema design, so you need to recognize when functional dependency analysis alone has stopped being enough.

As you watch the videos below, focus on three things: how an MVD is stated and how it differs from a functional dependency, what the sample table looks like before and after decomposition, and whether the join of the decomposed tables reproduces the original rows exactly. Also note where presenters disagree about how often 4NF matters in practice — that debate is part of the trade-off discussion for this topic.
