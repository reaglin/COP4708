Introduction

SQL is often described as a single language, but in practice it is a family of related sublanguages, each with a different job. Data Definition Language (DDL) is the part of SQL used to create and shape the structures that hold your data: tables, columns, data types, constraints, indexes, views, and schemas. Commands such as CREATE, ALTER, DROP, and TRUNCATE belong to DDL, and together they define what a database can store and what rules the stored data must obey.

This distinction matters in COP4708 because almost everything else you do depends on it. Queries written with SELECT (DQL) and data changes made with INSERT, UPDATE, and DELETE (DML) can only work within the structure that DDL has already established. Permissions (DCL) and transaction control (TCL) round out the picture. Getting comfortable naming these categories now will make the rest of the module, where you write real CREATE TABLE and ALTER TABLE statements, much easier to follow.

As you watch the videos below, keep a running list of which commands fall into which sublanguage, and notice how often DDL decisions, such as choosing a data type or adding a constraint, are decisions about data integrity rather than just syntax. Also pay attention to the commands that permanently change or remove structures, since those are the ones with the most serious consequences in a live database.
