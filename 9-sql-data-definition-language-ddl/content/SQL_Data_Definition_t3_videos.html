Introduction

Every column in a relational table has a data type, and that type is a promise about what the column may hold. Numeric types (INT, SMALLINT, BIGINT, DECIMAL/NUMERIC, FLOAT), character and string types (CHAR, VARCHAR, TEXT), date and time types (DATE, TIME, TIMESTAMP), and boolean or binary types (BOOLEAN, BLOB/BINARY) each store values differently and allow different operations. Choosing DECIMAL instead of FLOAT for currency, or DATE instead of VARCHAR for a birthdate, is not a stylistic preference — it determines whether the database can validate, sort, compare, and compute on your data correctly.

In this module you write CREATE TABLE statements, and the column definition is where the data type lives: a column name, a type (often with a length or precision, such as VARCHAR(50) or DECIMAL(10,2)), and any column-level constraints such as NOT NULL or DEFAULT. Data types are the first line of defense for data integrity; constraints build on top of them. Keep in mind that exact type names vary by DBMS (MySQL, SQL Server, Oracle, PostgreSQL, SQLite), so expect small differences between videos and your course environment.

As you watch, note three things: which type each presenter chooses for a given kind of value and why, how length or precision is specified, and how the data type sits alongside constraints inside the parentheses of a CREATE TABLE statement. Jot down any type names that differ from the ones your course uses so you can map them later.
