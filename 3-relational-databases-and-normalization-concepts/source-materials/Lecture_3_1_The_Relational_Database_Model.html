Lecture 3-1 - The Relational Database Model

Unique Properties of Relational Databases

Relational databases are distinguished from other data storage methods by several key properties:

  1. Structured Data: Relational databases store data in a structured format, using tables, rows, and columns. This makes it easier to organize, retrieve, and manipulate data.
  2. Normalization: Relational databases often employ normalization techniques to eliminate redundancy and ensure data integrity. This involves dividing data into multiple tables, reducing data duplication and improving database efficiency.
  3. Relationships: Relational databases establish relationships between tables through common fields (foreign keys). This allows for efficient data retrieval and manipulation based on related information.
  4. SQL: Relational databases are typically accessed and managed using SQL (Structured Query Language). SQL is a powerful and standardized language that provides a flexible way to query, manipulate, and update data.
  5. Data Integrity: Relational databases enforce data integrity through constraints like primary keys, foreign keys, and data types. This helps maintain data accuracy and consistency.
  6. Scalability: Relational databases can often scale to accommodate large datasets and high transaction volumes. While scalability can depend on factors like hardware and database design, relational databases are generally well-suited for handling large-scale data storage and retrieval.
  7. Flexibility: Relational databases are flexible and can be adapted to various data modeling needs. They can represent complex relationships and handle a wide range of data types.

These properties make relational databases a popular and versatile choice for storing and managing data in many applications, from small-scale databases to large-scale enterprise systems.

Entities and Attributes in a Relational Database Model

Entities

In a relational database model, an entity is a person, place, thing, or event that you want to track or store information about. It is a conceptual representation of a real-world object.

Examples of entities:

  • Customers
  • Products
  • Orders
  • Employees
  • Departments

Attributes

Attributes are the properties or characteristics of an entity. They describe the specific data points you want to collect about each entity.

Examples of attributes for the "Customers" entity:

  • CustomerID (primary key)
  • Name
  • Address
  • Email
  • Phone Number

Examples of attributes for the "Products" entity:

  • ProductID (primary key)
  • Name
  • Description
  • Price
  • QuantityInStock

Relationship between Entities and Attributes:

  • Each entity is defined by a set of attributes.
  • The attributes determine the specific information you want to store about each entity.
  • The combination of entities and their attributes forms the structure of a relational database.

In essence, entities and attributes are the fundamental building blocks of a relational database model. They provide a way to define and organize the data that will be stored and managed within the database.
