Weekly Module 2: Introduction to Database › Functional Dependency Key

Answer Key and Explanations

Valid Functional Dependencies:

  • StudentID → StudentName: ✅ Each student ID maps to exactly one name
  • StudentID → Major: ✅ Each student has one declared major
  • CourseCode → CourseName: ✅ Course codes uniquely identify course names
  • CourseCode → Credits: ✅ Each course has a fixed credit value
  • InstructorID → InstructorName: ✅ Each instructor ID maps to one name
  • (StudentID, CourseCode) → Grade: ✅ A student gets one grade per course (ignoring retakes)
  • InstructorName → InstructorID: ✅ No two instructors share the same name in this dataset

Invalid Functional Dependencies:

  • StudentID → GPA: ❌ Alice's GPA changes from 3.75 to 3.85 (GPAs change over time)
  • CourseCode → InstructorID: ❌ CS101 is taught by both I201 (Dr. Smith) and I307 (Dr. Taylor)
  • CourseCode → InstructorName: ❌ CS101 taught by both Dr. Smith and Dr. Taylor
  • RoomNumber → ClassSize: ❌ Room R205 has classes of size 30, 22, and 35
  • InstructorID → RoomNumber: ❌ I105 (Prof. Wilson) teaches in both R205 and R301
  • (CourseCode, Semester) → InstructorID: ❌ Even with semester, dependencies can fail
  • (CourseCode, Semester) → ClassSize: ❌ MATH201 in Spring2024 has 35 students vs Fall2023 with 30
  • Major → GPA: ❌ Computer Science majors have GPAs of 3.75, 3.85, and 2.85

Key Learning Points:

  1. Time-dependent attributes (like GPA) often violate functional dependencies
  2. Resource assignments (instructors to courses, rooms to classes) may vary by semester
  3. Capacity constraints (room sizes vs class sizes) don't always create dependencies
  4. Multiple valid assignments (same course, different instructors) break simple dependencies
  5. Composite keys are often needed for time-series or relationship data
