SQL, DML, and DDL

SQL (Structured Query Language) is a computer language used to communicate with and manipulate data stored in relational databases. It provides a standard way to interact with databases, allowing users to create, retrieve, update, and delete data.

DML (Data Manipulation Language) is a subset of SQL that is used to manipulate data within a database. It includes commands for inserting, updating, deleting, and retrieving data.

  • Basic DML commands:
    • INSERT: Adds new rows to a table.
    • UPDATE: Modifies existing data in a table.
    • DELETE: Removes rows from a table.
    • SELECT: Retrieves data from a table.

DDL (Data Definition Language) is another subset of SQL that is used to define and modify the structure of a database. It includes commands for creating, modifying, and dropping tables, databases, and other database objects.

  • Basic DDL commands:
    • CREATE: Creates new database objects like tables, databases, and indexes.
    • ALTER: Modifies the structure of existing database objects.
    • DROP: Removes database objects.

Example:

SQL
-- Create a table named "customers"
CREATE TABLE customers (
  customer_id INT PRIMARY KEY,
  first_name VARCHAR(50),
  last_name VARCHAR(50),
  email VARCHAR(100)   
);

-- Insert a new customer
INSERT INTO customers (customer_id, first_name, last_name, email)
VALUES (1, 'John', 'Doe', 'johndoe@example.com');

-- Update a customer's email
UPDATE customers
SET email = 'new_email@example.com'
WHERE customer_id = 1;

-- Delete a customer
DELETE FROM customers
WHERE customer_id = 2;

-- Retrieve all customers
SELECT * FROM customers;

In this example, we first create a table named "customers" using DDL. Then we use DML to insert a new customer, update an existing customer's email, and delete a customer. Finally, we use DML to retrieve all customers from the table.

The SQL CREATE TABLE Command

The CREATE TABLE command in SQL is used to define the structure of a new table within a database. It specifies the name of the table and the columns it will contain, along with their data types and any constraints or properties.

Basic Syntax

SQL
CREATE TABLE table_name (
    column1 data_type [constraints],
    column2 data_type [constraints],
    ...
);
  • table_name: The name you want to give to the new table.
  • column1, column2, ...: The names of the columns in the table.
  • data_type: The data type of each column (e.g., INT, VARCHAR, DATE, FLOAT).
  • constraints: Optional constraints that define rules for the data in the column, such as NOT NULL, PRIMARY KEY, UNIQUE, FOREIGN KEY, and more.

Examples

Creating a simple table:

SQL
CREATE TABLE customers (
    customer_id INT PRIMARY KEY,
    first_name VARCHAR(50),
    last_name VARCHAR(50),
    email VARCHAR(100)
);

This creates a table named "customers" with four columns: customer_id, first_name, last_name, and email. The customer_id column is declared as the primary key, which means it uniquely identifies each row in the table and cannot contain null values.  

Creating a table with more complex constraints:

SQL
CREATE TABLE orders (
    order_id INT PRIMARY KEY,
    customer_id INT,
    order_date DATE,
    total_amount DECIMAL(10, 2),
    FOREIGN KEY (customer_id) REFERENCES customers(customer_id)   
);

This creates a table named "orders" with columns for order ID, customer ID, order date, and total amount. The FOREIGN KEY constraint specifies that the customer_id column in the "orders" table must reference a valid customer_id in the "customers" table, ensuring data integrity.

Creating a table with a default value:

SQL
CREATE TABLE products (
    product_id INT PRIMARY KEY,
    product_name VARCHAR(100),
    price DECIMAL(10, 2) NOT NULL DEFAULT 0.00
);

This creates a table named "products" with columns for product ID, product name, and price. The DEFAULT clause specifies that the price column will have a default value of 0.00 if no value is provided when inserting a new row.

By understanding the CREATE TABLE command and its syntax, you can effectively design and create tables to store your data in a relational database.

Foreign Key Constraint

A foreign key constraint in a relational database establishes a link between a column in one table (the child table) and a primary key or unique column in another table (the parent table). It ensures data integrity by maintaining referential consistency between the two tables.

How Foreign Keys Work

  • Referential Integrity: A foreign key constraint guarantees that the values in the foreign key column of the child table must match existing values in the referenced column of the parent table. This prevents orphaned records in the child table.
  • Data Consistency: By enforcing relationships between tables, foreign keys help maintain data consistency and prevent errors caused by inconsistent or incorrect data.
  • Data Validation: Foreign keys can be used to validate data input, ensuring that only valid values are inserted into the child table.

Example

Consider two tables: customers and orders. The orders table might have a customer_id column that references the customer_id column in the customers table.

SQL
CREATE TABLE customers (
    customer_id INT PRIMARY KEY,
    first_name VARCHAR(50),
    last_name VARCHAR(50)
);

CREATE TABLE orders (
    order_id INT PRIMARY KEY,
    customer_id INT,
    order_date DATE,
    FOREIGN KEY (customer_id)    REFERENCES customers(customer_id)
);

In this example:

  • The customer_id column in the orders table is declared as a foreign key.  
  • The REFERENCES customers(customer_id) clause specifies that the customer_id in orders must match a valid customer_id in the customers table.
  • If you try to insert an order with a customer_id that doesn't exist in the customers table, the database will raise an error, preventing data inconsistency.

Benefits of Foreign Keys:

  • Data Integrity: Ensures data consistency and prevents orphaned records.
  • Data Validation: Helps enforce data validation rules.
  • Relationship Modeling: Defines relationships between tables in a database.
  • Data Analysis: Facilitates data analysis by providing links between related data.

By understanding and using foreign key constraints, you can create more robust and reliable database designs.

Adding a Foreign Key to an Existing Table

Understanding the Scenario:

Let's assume we have two tables: orders and customers. We want to establish a relationship between the two tables, where each order belongs to a specific customer. To achieve this, we'll add a foreign key constraint to the orders table, referencing the customer_id in the customers table.

SQL Statement:

SQL
ALTER TABLE orders
ADD CONSTRAINT fk_orders_customers
FOREIGN KEY (customer_id) REFERENCES customers(customer_id);

Explanation:

  1. ALTER TABLE orders: This specifies that we want to modify the structure of the orders table.
  2. ADD CONSTRAINT fk_orders_customers: This indicates that we're adding a new constraint named fk_orders_customers. You can choose any meaningful name for the constraint.
  3. FOREIGN KEY (customer_id): This defines the column in the orders table that will be the foreign key. In this case, it's the customer_id column.
  4. REFERENCES customers(customer_id): This specifies that the customer_id in the orders table must reference the customer_id in the customers table.

Important Considerations:

  • Column Existence: Ensure that the column you're specifying as the foreign key exists in both tables.
  • Data Types: The data types of the foreign key column and the referenced column should match.
  • Referential Integrity: The foreign key constraint will enforce referential integrity, preventing you from inserting or updating orders with invalid customer IDs.
  • Index: For performance reasons, it's often recommended to create an index on the foreign key column.

Example with an Index:

SQL
ALTER TABLE orders
ADD CONSTRAINT fk_orders_customers
FOREIGN KEY (customer_id) REFERENCES customers(customer_id),
ADD INDEX idx_orders_customer_id (customer_id);

This statement adds both the foreign key constraint and an index on the customer_id column in the orders table.

By following these steps, you can effectively add foreign key constraints to existing tables to establish relationships and maintain data integrity in your database.
