Introduction

Up to this point you have met relational, NoSQL, and hierarchical databases one at a time. This topic places them side by side so you can see how their structures, schemas, query languages, scaling behavior, and consistency guarantees differ — and, more importantly, why those differences matter when someone has to pick one for a real system.

There is no "best" database. A rigid schema that feels restrictive in one project is exactly what protects financial records in another; a flexible document store that speeds up a startup's prototype can quietly allow inconsistent data later. The goal here is to build a mental checklist of selection criteria: What does the data look like? How will it be queried? How much will it grow? How costly is an inconsistent read?

As you watch the two videos below, keep a comparison table in your notes with columns for structure, schema flexibility, query power, scalability, and integrity. Note the vocabulary each speaker uses (normalization, joins, ACID, horizontal versus vertical scaling, eventual consistency) and jot down the example use cases they mention — you will be asked to justify database choices for similar scenarios later in this module.
