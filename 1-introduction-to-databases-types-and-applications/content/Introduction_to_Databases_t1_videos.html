Introduction

A database is an organized collection of data stored so that it can be efficiently retrieved, updated, and managed. Before we can compare database types or design one, we need a shared vocabulary: data versus information, records, fields, and tables, and the software layer — the database management system (DBMS) — that sits between users and the stored data. This topic builds that foundation.

This matters for everything that follows in COP4708. Later in the module you will distinguish relational, NoSQL, and hierarchical models and choose the right one for a given scenario. Those decisions only make sense once you can say precisely what a database is, what problems it solves that a spreadsheet does not, and what a DBMS actually does for you (storage, querying, concurrent access, security, and integrity).

As you watch, keep a running glossary. Note how each speaker defines a database, where tables, rows (records), and columns (fields) appear, and when the discussion shifts from the data itself to the DBMS that manages it. Also notice any mention of selection criteria — scalability, structure, consistency — since those terms return later in the module.
