Introduction

Hierarchical databases organize information as a tree: a single root record branches into child records, and each child has exactly one parent. This structure was the dominant approach in early commercial database systems such as IBM's IMS, and it still shapes how we think about nested data today — think of file systems, organizational charts, or XML and JSON documents. Because relationships are built directly into the storage structure through parent-child links, navigating a hierarchical database means following those links from the root downward rather than writing a declarative query.

In this course, hierarchical databases matter for two reasons. First, they give you historical context: understanding what came before the relational model makes it much clearer why tables, keys, and SQL were such an important advance. Second, they sharpen your ability to compare models — hierarchical databases are fast and predictable for queries that follow the tree, but awkward or impossible for many-to-many relationships and for questions the designer did not anticipate.

As you watch, look for three things: how the tree structure and parent-child rule are defined, how data access and navigation differ from relational querying, and where each model's strengths and limitations show up. Note that the third video shifts from data models to B-trees, an internal tree structure used inside modern database engines — keep that distinction clear in your notes, since a tree-shaped index is not the same thing as a hierarchical data model.

About this video

An animated explanation of B-trees, the balanced tree data structure widely used for indexing in databases and file systems. The video should show how a B-tree keeps data sorted and searchable, how nodes split as data grows, and why this keeps lookups fast on very large datasets. This is about internal storage and indexing, not about the hierarchical data model.

Why this video

Spanning Tree is a well-regarded explainer channel, and this video builds your intuition for tree-based organization and navigation — useful background that also helps you avoid confusing a tree-shaped index with a hierarchical database model.
