Introduction

Before you write a single CREATE TABLE statement, someone has to decide what things the database must keep track of, what facts describe each of those things, and how those things relate to one another. That work is logical data modeling. A logical model names the entities in a business domain, lists their attributes, identifies which attribute (or combination) uniquely identifies each instance, and records the relationships and rules that connect entities — all without committing to a particular database product or SQL dialect.

In this module, the logical model is the bridge between understanding a business problem and expressing it in SQL. Entities become tables, attributes become columns, unique identifiers become primary keys, relationships become foreign keys, and business rules become constraints. Normalization — organizing attributes so each fact is stored once, in the place it belongs — is done at the logical level so that the schema you later define is free of avoidable redundancy and update problems.

As you watch the videos below, keep a translation column in your notes. For every modeling term you hear (entity, attribute, cardinality, identifier, many-to-many relationship, bridge table), write the SQL element it will become. Pay particular attention to how one-to-many and many-to-many relationships are represented, since those decisions drive the foreign key and junction-table work you will do in the hands-on portion of this module.

How These Videos Support the Learning Outcomes

Together these videos establish the modeling vocabulary that the rest of the module converts into SQL.
