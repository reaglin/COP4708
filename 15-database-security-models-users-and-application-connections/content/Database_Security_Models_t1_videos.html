Introduction

Database security begins long before you type a GRANT statement. It starts with a set of principles that tell you what you are protecting, from whom, and how much access any given person or program should have. In this topic you will meet those principles: the CIA Triad (confidentiality, integrity, availability), the distinction between authentication and authorization, the principle of least privilege, and the layered approach known as defense in depth.

These ideas matter in COP4708 because every practical task later in the module is an application of them. Creating users and roles is authorization in action; using parameterized queries protects integrity and confidentiality; storing credentials outside your code and encrypting connections are defense-in-depth layers; and choosing a limited service account for an application is least privilege applied to software rather than people. If the principles are clear, the SQL and configuration choices stop feeling arbitrary.

As you watch, keep a running list of two things. First, which part of the CIA Triad each control protects, since many controls protect only one or two and you need combinations to cover all three. Second, where the database sits relative to other defenses: notice that the database is rarely the first line of defense, but it is often the last, which is why access control inside the database still matters even when a network firewall and an application layer stand in front of it.

How These Videos Support the Learning Outcomes

Together these videos build the conceptual base the rest of the module depends on. The CIA Triad video and the security principles video directly support MO1 by explaining confidentiality, integrity, availability, and least privilege as frameworks rather than slogans. The least privilege and defense-in-depth discussion also sets up MO2, since roles, GRANT, and REVOKE are the mechanisms by which least privilege and separation of duties are enforced inside a database, and MO4, where a limited service account, external credential storage, and encrypted connections each form a separate defensive layer. The database security overview previews the threat categories behind MO3 and MO5, including injection attacks and the risks of shared or improperly isolated connections. None of the videos walk through SQL syntax or connection pool configuration, so expect the readings and lab work in this module to supply those hands-on steps.
