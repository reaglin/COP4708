Introduction

Relational databases deliberately split information across multiple tables to avoid duplication: customers live in one table, orders in another, products in a third. That design keeps data clean, but it means almost every useful question you ask will require pulling columns from more than one table at a time. JOINs are the SQL mechanism that makes this possible, matching rows from one table to rows in another based on a shared key.

In this topic you will work through the four primary JOIN types. An INNER JOIN returns only rows that have a match on both sides. A LEFT JOIN keeps every row from the left table and fills in NULLs where no match exists on the right; a RIGHT JOIN does the mirror image; and a FULL JOIN preserves unmatched rows from both tables. The differences matter enormously in practice — the same query written with INNER instead of LEFT can silently drop the customers who have not yet placed an order, which is often exactly the group you were trying to count.

As you watch the videos below, pay close attention to three things: the join condition (the ON clause and which columns it compares), where NULLs appear in the result set and why, and how table aliases keep multi-table queries readable. When a video shows a diagram or animation, try to connect the picture back to the actual rows in the result table rather than memorizing the shape alone. Then practice writing the queries yourself — JOIN syntax becomes intuitive quickly once you have typed a dozen of them.
