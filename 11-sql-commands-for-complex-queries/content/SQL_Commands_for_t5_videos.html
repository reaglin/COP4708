Introduction

Up to this point, most of your queries have returned individual rows. GROUP BY changes that perspective: instead of looking at each row on its own, you collapse rows that share a common value into a single summary row. Combined with aggregate functions such as COUNT, SUM, AVG, MIN, and MAX, GROUP BY lets you answer questions like "how many orders did each customer place?" or "what is the average salary in each department?" — the kind of statistical summaries that turn raw stored data into useful information.

HAVING is the companion clause that filters those summary groups. A common source of confusion is why you cannot simply put an aggregate condition in WHERE, and the answer lies in query execution order: WHERE filters individual rows before grouping happens, while HAVING filters the groups after the aggregates have been calculated. Keeping that sequence straight (FROM, WHERE, GROUP BY, HAVING, SELECT, ORDER BY) is the single most helpful mental model for this topic, and it is also exactly what the module outcomes ask you to be able to explain.

As you watch the videos below, pay attention to three things: which columns appear in the SELECT list versus the GROUP BY list, where each example places a filtering condition and why, and how the final query reads from top to bottom once GROUP BY and HAVING are combined. Try pausing and predicting the result set before the presenter runs the query — that habit will prepare you well for the module assignments.
