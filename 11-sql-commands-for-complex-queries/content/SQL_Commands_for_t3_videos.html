Introduction

Every SQL query you write returns rows, but rarely do you want all of them. The WHERE clause is the mechanism that lets you state, precisely and declaratively, which rows qualify: customers in a particular region, orders above a dollar threshold, product names that begin with a certain prefix, or records where a value was never recorded at all. Understanding WHERE is the foundation for nearly everything else in this module, because joins, grouped summaries, and subqueries all depend on your ability to express conditions accurately.

In this topic you will work through the building blocks one at a time: the basic structure of a WHERE clause, the comparison operators (=, <>, <, >, <=, >=, BETWEEN), the logical operators AND, OR, and NOT, pattern matching with LIKE and its wildcards, set membership with IN and NOT IN, and the special handling that NULL requires through IS NULL and IS NOT NULL. The last subtopic ties these together: combining several conditions in one predicate, where operator precedence and parentheses determine whether your query means what you think it means.

As you watch the videos below, pay attention to the exact syntax used, especially how string literals are quoted, how wildcards (% and _) behave, and why NULL cannot be tested with the equals sign. Try pausing and predicting which rows a given condition will return before the presenter runs the query — that habit is what turns syntax recognition into real query-writing skill.
