Lecture 11-1 - Database Design using Normalization

Video Lecture

Data Normalization

Data normalization is a process of organizing data in a database to minimize redundancy and improve data integrity. It involves breaking down large tables into smaller, more focused tables, reducing the potential for anomalies like insertion anomalies, deletion anomalies, and update anomalies.

Why Normalization is Performed

  1. Reduce Redundancy: By eliminating duplicate data, normalization reduces storage requirements and improves query performance.
  2. Improve Data Integrity: It helps prevent inconsistencies and anomalies that can occur when data is stored in a non-normalized format.
  3. Enhance Data Maintainability: Normalized databases are easier to maintain and update as changes can be made more efficiently.

Denormalization

Denormalization is the process of intentionally introducing redundancy into a database by combining tables or adding redundant columns. This is sometimes done to improve query performance, especially when certain queries are frequently executed and involve joins between multiple tables.

Normal Forms

There are several normal forms, each building upon the previous one to achieve a higher level of normalization.

  1. First Normal Form (1NF):

    • Each column in a table should contain atomic values (i.e., values that cannot be further divided).
    • No repeating groups within a row.

  2. Second Normal Form (2NF):

    • The table must be in 1NF.
    • All non-key attributes must be fully dependent on the primary key.

  3. Third Normal Form (3NF):

    • The table must be in 2NF.
    • No non-key attribute should be transitively dependent on the primary key.

  4. Boyce-Codd Normal Form (BCNF):

    • The table must be in 3NF.
    • Every determinant must be a superkey.

  5. Fourth Normal Form (4NF):

    • The table must be in BCNF.
    • The table must not contain any multivalued dependencies.

Choosing the Right Normal Form:

The appropriate normal form depends on the specific requirements of the application and the trade-offs between data integrity and performance. While higher normal forms generally lead to better data integrity, they can sometimes result in more complex queries and slower performance. In practice, a balance is often sought between normalization and denormalization to optimize both data quality and query efficiency.

Example of Putting Data into BCNF

Understanding BCNF:

Boyce-Codd Normal Form (BCNF) is a higher level of normalization than 3NF. A table is in BCNF if every determinant (a set of attributes that determines all other attributes in the table) is a superkey (a set of attributes that can uniquely identify a row).

BCNF is chosen for this example as it represents good design practices and goes one step past 3NF, which is the most common normal form used in database design.  

Example Scenario:

Let's consider a table named Orders with the following attributes:

  • Order_ID (primary key)
  • Product_ID
  • Customer_ID
  • Product_Name
  • Customer_Name

In this example, Product_ID and Customer_ID together determine Product_Name and Customer_Name. However, Product_ID alone cannot determine Customer_Name, and Customer_ID alone cannot determine Product_Name.

Identifying the Violation:

This table is not in BCNF because Product_ID and Customer_ID are determinants but not superkeys. To bring it into BCNF, we need to decompose it into two smaller tables.

Decomposing the Table:

  1. Create a new table:
    SQL
    CREATE TABLE Products (
    Product_ID PRIMARY KEY,
    Product_Name
);
  2. Modify the existing table:
    SQL
    ALTER TABLE Orders
DROP COLUMN Product_Name,
DROP COLUMN Customer_Name,
ADD FOREIGN KEY (Product_ID) REFERENCES Products(Product_ID);

Explanation:

  • We created a new table Products to store the Product_ID and Product_Name attributes.
  • In the Orders table, we removed the Product_Name and Customer_Name columns.
  • We added a foreign key constraint in the Orders table to reference the Product_ID in the Products table, establishing a relationship between the two tables.

Result:

After this decomposition, both the Orders and Products tables are now in BCNF. The determinants in each table are superkeys, ensuring that the data is properly normalized and avoiding anomalies.
